Review architecture

Separate acquisition, transformation, and interpretation

The proposed design keeps source records intact and prevents experimental encodings from being confused with agency products.

01Acquire

Source adapters

Retrieve metadata or observations from documented public endpoints with timestamps, identifiers, and source URLs.

  • NASA CMR granule metadata
  • NOAA NEXRAD product access
  • NOAA CO-OPS station observations
→
02Normalize

Typed records

Preserve units, quality flags, spatial bounds, latency, and provenance before any experimental transformation.

  • Schema validation
  • Unit normalization
  • Quality-control flags
→
03Experiment

Setun encoding

Map bounded scalar values into balanced-ternary software words for comparison with conventional representations.

  • Deterministic conversion
  • Round-trip tests
  • No hardware-performance claim
→
04Evaluate

Traceable outputs

Compare error, latency, storage, and decision usefulness against a binary baseline with reproducible notebooks or reports.

  • Baseline comparison
  • Uncertainty disclosure
  • Exportable audit trail

Software demonstration

Balanced-ternary transformation—not a new sensor

The interactive calculation calls AMOC’s existing Setun API. It demonstrates encoding behavior only.

ReadyRun the reference encoderAPI: /api/setun/encode
Interpretation rule

The output is a deterministic representation of the supplied number. It is not a satellite measurement, NOAA product, quantum state, or evidence of improved forecasting skill.

Low-risk collaboration proposal

A 30-day historical-data pilot

Use one bounded coastal question and archived public records to test whether the prototype adds measurable value without touching operational systems.

  1. Week 1Define the questionSelect one region, outcome, source products, baseline, and acceptance criteria with a domain reviewer.
  2. Week 2Build traceable adaptersCache source responses, retain identifiers and quality flags, and document transformations.
  3. Week 3Run the comparisonEvaluate conventional and balanced-ternary representations on identical historical inputs.
  4. Week 4Report honestlyPublish accuracy, latency, failure cases, reproducibility notes, and a go/no-go recommendation.
Questions for a technical reviewer

Where expert feedback matters most

  • Which public products and quality flags best fit a bounded AMOC/coastal test?
  • What latency and spatial resolution would make a prototype comparison meaningful?
  • Which baseline model or workflow should the experiment avoid duplicating?
  • What evidence threshold should be met before discussing operational relevance?
